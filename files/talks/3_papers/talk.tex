\subsection{Firefly: Verified Tool-Call Data from Real APIs}

\begin{frame}{Scalable, Real, Verifiable: Pick Two}
  \centering
  \figorplaceholder[.7\textheight]{figures/firefly/pick-two.png}{Three panels, yellow robot style. Left ``Human annotation'': one tired robot hand-writes tool-call examples while a wall of hundreds of APIs waits (reliable, but expensive and cannot cover the long tail of real APIs). Middle ``Simulated APIs'': robot plays with a cardboard toy server while the real server behind glass answers differently (responses diverge from real API behavior). Right ``Task first'': robot writes a task, then imagines a chain of tool calls ending in a question mark with a crossed-out answer (no ground-truth trajectory or final state to verify against).}\\[6pt]
  {\small {\color{barneg}\faTimes}~not scalable \qquad {\color{barneg}\faTimes}~not real \qquad {\color{barneg}\faTimes}~not verifiable}
  % Speaker (paper intro, para 1): training needs large-scale trajectories with correct intermediate calls and
  % verifiable outcomes. Human annotation is reliable but expensive and domain-specific. Synthetic pipelines either
  % simulate the tools (responses drift from real APIs) or generate tasks first over real tools (no ground truth).
\end{frame}

\begin{frame}[standout]
  How can we get tool-call training data that is \ul{scalable}, \ul{real}, and \ul{verifiable} at the same time?
\end{frame}

\begin{frame}{Recap}
  \begin{outline}
    \1 Designing: UXAgent lets UX researchers iterate on a study design before spending participants' time.
    \1 Evaluating: against real behavioral data, prompted agents are far from human; fine-tuning with reasoning helps, but SFT can only imitate.
    \1 Improving: WebServ gives agents a scalable place to act, Firefly a verified signal to learn from; RL takes a 4B model to Claude Sonnet level.
